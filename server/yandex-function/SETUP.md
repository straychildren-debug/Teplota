# Настройка функции в Yandex Cloud (доставка в MAX)

Токен нигде в коде и в репозитории не хранится — только в переменных
окружения функции. Впишете его сами в консоли.

## 1. Куда вписать токен

Консоль Yandex Cloud → **Cloud Functions** → ваша функция `teplota-lead`
→ создать новую версию → блок **Переменные окружения**:

| Имя | Значение |
|---|---|
| `MAX_BOT_TOKEN` | токен бота из MAX |
| `MAX_CHAT_ID` | id чата, куда падают заявки |
| `ALLOWED_ORIGINS` | `https://teplota.su,https://www.teplota.su` |

**Получателей может быть несколько.** И `MAX_CHAT_ID`, и `MAX_USER_ID`
принимают список через запятую, и их можно задать вместе — заявка
уйдёт всем перечисленным:

```
MAX_USER_ID = 458912064,111222333
MAX_CHAT_ID = -70123456
```

Если кто-то из получателей заблокировал бота или удалил переписку,
заявка всё равно дойдёт остальным: функция считает отправку успешной,
когда сообщение принято хотя бы одним адресатом. Кому не ушло —
видно в логах функции.

Для команды из нескольких человек надёжнее один групповой чат, а не
список личек: история в одном месте, и новый сотрудник подключается
без правки переменных.

`ALLOWED_ORIGINS` — через запятую, без пробелов и без слэша на конце:
браузер сверяет адрес символ в символ.

Где взять токен в MAX: **Чат-боты → Расширенные настройки → Настроить**.

## 2. Обновить код

В том же окне создания версии, в редакторе кода, замените содержимое
`index.js` на файл из этой папки. Точка входа прежняя: `index.handler`.
Галочка **Публичная функция** должна остаться включённой.

Сохраните — создастся новая версия.

## 3. Узнать, чей это бот, и найти MAX_CHAT_ID

Откройте `https://functions.yandexcloud.net/<id-функции>?selftest=1`

Функция покажет три вещи:

* **бот** — имя, никнейм и id того бота, чей токен вписан. Так можно
  убедиться, что подключён нужный, а не какой-то старый;
* **события** — последние сообщения бота, в них видно `chat_id`;
* **переменные** — что задано, а что нет.

Значение токена наружу не отдаётся.

Чтобы события появились: напишите боту сообщение. Для группового чата
добавьте бота туда **администратором** — иначе события из группы он не
получает.

Найденный `chat_id` впишите в `MAX_CHAT_ID` и сохраните версию.

Быстрая проверка токена без функции — команда в PowerShell:

```
curl -H "Authorization: ВАШ_ТОКЕН" https://platform-api2.max.ru/me
```

Просто вставить этот адрес в браузер не выйдет: токен передаётся
заголовком, браузер его не отправит.

Тот же `?selftest=1` показывает, доступен ли MAX с площадки Yandex
Cloud и какие переменные заданы. Секретов в ответе нет.

## 4. Проверка

Откройте сайт, заполните форму, отправьте. Должен появиться экран
«Заявка принята», а в MAX — сообщение.

Если не пришло — на странице функции есть вкладка с логами, там будет
код ответа MAX и причина. Наружу функция подробности не отдаёт намеренно.

## Если MAX окажется недоступен

Тогда заявка не потеряется: форма молча откроет почтовый клиент
посетителя с готовым письмом на `teplota16@bk.ru`. Ошибку посетитель
не увидит. Это тот же запасной путь, что работал и раньше.

## Коды ошибок

| Код | Что означает |
|---|---|
| `forbidden_origin` | домен сайта не совпал со списком `ALLOWED_ORIGINS` |
| `bad_phone` | в телефоне меньше 10 цифр |
| `bad_request` | тело запроса не разобралось как JSON |
| `too_many` | больше 15 заявок в час с одного адреса |
| `not_configured` | не заданы токен или id чата |
| `upstream` | MAX не ответил — смотрите лог функции |

## Проверка отправки

`?selftest=1&send=1` шлёт пробное сообщение каждому получателю из
переменных и показывает ответ MAX по каждому отдельно. Так видно, какой
именно id не работает и почему: неверный номер, бот заблокирован или
диалог не начат.

Частые ответы MAX:

| Ответ | Что делать |
|---|---|
| `chat not found` | id не тот. Возьмите настоящий из блока «события» |
| `403` / `blocked` | получатель заблокировал бота |
| `код 0, timeout` | MAX не ответил, повторите |

## Замечания по MAX, на которые уже напоролись

* `/updates` работает длинным опросом и по умолчанию держит соединение
  до 30 секунд. В запросе обязателен `timeout=0`, иначе диагностика
  упирается в дедлайн и показывает ложный таймаут.
* Таймаут самой функции ставьте **30 секунд**, а не 15: при пятнадцати
  функция не успевает ответить, если MAX отвечает медленно.
* Чтобы бот мог написать человеку в личку, этот человек должен сам
  сначала написать боту. Если один из получателей этого не сделал,
  заявка ему не уйдёт — остальным дойдёт, а в логах будет отказ.
