# Приём заявок с сайта

`lead.js` — serverless-функция: принимает POST с формы и отправляет заявку
в Telegram. Токен бота живёт в переменных окружения хостинга и в браузер
не попадает никогда.

## Переменные окружения

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | куда слать заявки: свой id, id группы (отрицательный) или `@имя_канала` |
| `ALLOWED_ORIGIN` | домен сайта, например `https://teplota.su` |

Задаются в панели хостинга, **не в репозитории**. Если токен хоть раз
попал в git, чат или переписку — отзовите его в @BotFather (`/revoke`)
и выпустите новый.

## Как узнать TELEGRAM_CHAT_ID

1. Напишите боту любое сообщение. Для группы — добавьте бота в неё и
   напишите там.
2. Откройте в браузере `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
3. В ответе найдите `"chat":{"id":...}` — это нужное число.

Ссылку с токеном никому не показывайте и не сохраняйте в закладки.

## Где это работает

Функция выполняется только там, где хостинг это умеет: Vercel, Netlify,
Cloudflare. **На GitHub Pages серверных функций нет** — там адрес
`/api/lead` вернёт 404.

Это предусмотрено: получив 404, форма не показывает ошибку, а открывает
почтовый клиент посетителя с заполненным письмом на адрес из
`FORM_EMAIL` (см. `public/js/app.js`). Заявка не теряется, но часть
посетителей письмо не отправит — поэтому для нормальной работы формы
сайт нужно перевести на хостинг с функциями.

## Проверка

Локально форму можно прогнать без Telegram: поднимите любой сервер,
отвечающий на `POST /api/lead` кодом 200, и отправьте заявку. Тело
запроса — плоский JSON, ключи совпадают с подписями полей формы:

```json
{
  "Ваше имя": "Марат",
  "Телефон": "+7 (905) 313-34-53",
  "Что нужно сделать": "Монтаж отопления",
  "Объект": "Частный дом 140 м², два этажа",
  "Комментарий": "",
  "Страница": "https://teplota.su/"
}
```
